# Isonique workflow comparison

This reference records the workflows available in Isonique. Notes on Apple’s discontinued Aperture 3 provide historical context where relevant. The initial comparison used Isonique commit `0ebda9a` on 9 November 2026. Only the native Swift/SwiftUI/AppKit macOS app is maintained. The Swift package has a UI executable, an IsoniqueCore library, XCTest and no external package dependencies. ImageIO handles decoding and encoding, Core Graphics runs an 8-bit sRGB pipeline, and CryptoKit supplies SHA-256. Libraries store an atomic JSON catalogue and byte-verified originals on disk. UserDefaults holds several app-level options. There are no web/PWA, iOS, Android, Windows or other maintained app sources. See the [compatibility inventory](../COMPATIBILITY.md) for legacy catalogue evidence and [test results](TEST_RESULTS.md) for what was exercised.

## Historical sources and scope

- Apple introduced Faces, Places, non-destructive Brushes, adjustment presets, richer full-screen browsing and multimedia slideshows in Aperture 3. The Apple-authored launch and 3.5 manuals establish workflows and controls. The supplied 908-page PDF exceeded the browser extractor limit, and direct download returned HTTP 403. The 3.5 guide's complete text and the mirrored Apple Help supplied the detailed baseline. - The 3.5 guide documents the unified iPhoto library, iCloud shared streams, SmugMug and Apple Maps workflows. Apple’s 3.4.5 update addressed camera/card deletion and ejection. The contemporaneous 3.6 release-note transcription identifies Yosemite compatibility and fixes for soft proofing performance, shared streams, writing IPTC to originals and Library First Aid. It separately reports RAW Decode 6. The original 3.6 support link did not load. [Apple 3.4.5 release notes](https://support.apple.com/en-me/106572), [3.6 release-note transcription](https://www.photojoseph.com/tips/2014/10/20/aperture-36-release-notes-and-raw-engine-v6)
- Historical command reference is the Apple shortcut card plus the 3.5 guide’s workspace and individual workflow sections. The table records representative commands and gaps. The historical shortcut comparison draws on those published references. [Apple shortcut card mirror](https://www.yumpu.com/en/document/view/55992561/apple-aperture-3-keyboard-shortcuts-aperture-3-keyboard-shortcuts), [Command Editor help](https://aperture.skydocu.com/en/customize-the-aperture-workspace/customize-keyboard-shortcuts/overview/)

Statuses refer to the feature scope named in each row. “Fully implemented and tested” requires verified operation and integration for that scope. Existing code without enough evidence for that label is marked as needing improvement or partial. Historical workflow and modern design choices are tracked separately.

## Library, selection and metadata

| Workflow | Status | Isonique implementation |
| --- | --- | --- |
| Create and switch independent Isonique libraries | Fully implemented and tested | File → New Isonique Library (⇧⌘N) creates a new folder. File → Open Isonique Library verifies and switches libraries. Both commands exercised in the native app. Normal launch remembers the selected path. |
| Library recents and relocation | Partially implemented | File → Open Recent Library switches between up to ten saved library paths. The same verified opener is used when selecting a library from a new location. Finder document opening remains open. Aperture provided a Switch to Library submenu. [Aperture Help](https://aperture.skydocu.com/en/work-with-projects-and-the-library/work-with-library-files/view-other-libraries/) |
| Stale catalogue write protection (modern safeguard) | Fully implemented and tested | Independently opened workspaces save against the catalogue they loaded. A stale edit or Undo cannot overwrite a newer save. File → Reload Library reads the latest catalogue, keeps valid navigation and restores persisted history when enabled. |
| Managed originals and byte-exact original export | Implemented but needs improvement | SHA-256-verified copies and original export have automated coverage. Missing managed originals can be restored individually or in a batch from matching bytes. |
| Folder-based recovery for managed originals | Fully implemented and tested | The File menu restores verified copies from a backup or folder into their existing managed paths. Search can target selected photos, the current project or the entire library. It reports unmatched files, ambiguous copies and blocked destinations. Each completed copy remains available after cancellation or restart. |
| Referenced originals, offline badges, reconnect, relocate, consolidate | Partially implemented | Optional referenced import, offline browser filter, verified single-file relink and copy consolidation. Relocation handles managed and referenced originals. Offline previews remain open. |
| Original relocation and reusable destination presets | Fully implemented and tested | File → Relocate Originals offers built-in choices and reusable named filename/subfolder templates. The preview shows exact paths, storage-name fallbacks, verified reuse and skipped paths. Apply copies each shared original once, saves all version references, and then releases eligible old files. Keeping old referenced files is the default. [Aperture Help](https://aperture.skydocu.com/en/work-with-projects-and-the-library/work-with-referenced-images/) |
| Batch consolidation into managed storage | Fully implemented and tested | Select Photos and File → Consolidate Selected Originals copy verified originals into the library and update all shared versions in one catalogue save. External originals are preserved. Aperture offered copy and move choices for consolidation. [Aperture Help](https://aperture.skydocu.com/en/work-with-projects-and-the-library/work-with-referenced-images/) |
| Folder-based reconnect for referenced originals | Fully implemented and tested | The File menu searches a folder and its subfolders for known names, verifies fingerprints and saves shared-version paths together. It reports unmatched and ambiguous originals and can target selected photos, the current project or the entire library. Aperture 3.5 supported reconnecting a selection or project from its Locate Referenced Files dialog. [Aperture Help](https://aperture.skydocu.com/en/work-with-projects-and-the-library/work-with-referenced-images/) |
| Projects, albums, sidebar navigation and project overview/skimming | Partially implemented | Flat projects and albums; membership, filters and sidebar navigation. No project covers or skimming. |
| Nested folders and albums under projects; drag/drop and manual ordering | Missing | Sidebar groups are display sections only. |
| Smart Albums and compound search | Partially implemented | Live All/Any rules for name, caption, keyword, camera, capture/import day, rating, flag, extension, adjustment status and original storage/availability. Smart Albums can be project-scoped. Advanced Search shares the rules and can save them as an album. Color labels and the four core IPTC fields also work in compound rules. Five EXIF fields also have typed rules. GPS rules cover signed coordinates, a radius and indexing status. Nested groups, broader EXIF/IPTC rules and person predicates are pending. |
| Import-session, paired-media and photo-usage search | Partially implemented | Import date and file-extension rules are available, and RAW/JPEG pair membership is visible in Info. Aperture also exposed import-session, paired-media and photo-usage rules in the Filter HUD. Those dedicated criteria are pending. [Aperture 3.5 Help](https://aperture.skydocu.com/en/organize-and-sort-photos/search-for-photos/search-using-a-combination-of-criteria/) |
| Manual and automatic stacks, picks, album picks, expand/collapse | Partially implemented | Manual and capture-time groups, persistent global and regular-album picks, Undo/Redo for pick changes, and collapsed Browser covers. Filtered-out or trashed picks fall back to matching members. Promote, demote and drag reorder remain open. [Aperture Help](https://aperture.skydocu.com/en/organize-and-sort-photos/stack-photos/set-a-pick-photo-for-a-stack/) |
| Original/adjusted display, create and duplicate independently editable versions | Implemented but needs improvement | Neutral and duplicate versions share an original, with separate recipes, names, metadata, Trash and history. Legacy named snapshots remain available. Automatic stacking and duplicate selection modifiers are pending. [Aperture Help](https://aperture.skydocu.com/en/organize-and-sort-photos/set-up-and-arrange-photos/create-versions-of-a-photo/) |
| Ratings, rejected state, flags and color labels | Fully implemented and tested | Recovered rating bounds and filters. Keyboard and menu actions for single and batch review, seven color labels with custom names, browser and Smart Album filters, persisted catalogue metadata and Undo. |
| Reusable keyword groups and quick editing | Fully implemented and tested | Metadata → Manage Keyword Groups saves named sets across libraries. View → Show Keyword Controls displays the active group. Click a keyword or Apply Group to append to the visible selection. Shift-click or use Metadata → Remove Keyword to remove a keyword. With the Browser or Viewer focused, Option–1 through Option–8 assign keywords by group order and adding Shift removes them. Each edit is one Undo step. The active group and controls persist. [Aperture 3.5 Help](https://aperture.skydocu.com/en/organize-and-sort-photos/add-keywords-to-photos/apply-keywords-using-keyword-controls-and-presets/) |
| Hierarchical keyword vocabulary and text exchange | Fully implemented and tested | Metadata → Keyword Vocabulary manages reusable trees across libraries, applies a selected term to photos, and imports or exports tab-indented UTF-8 lists. Case-insensitive matches merge within each branch. Photo assignments store the full vocabulary path alongside flat tags. [Aperture 3.5 Help](https://aperture.skydocu.com/en/organize-and-sort-photos/add-keywords-to-photos/export-and-import-keyword-lists/) |
| Keyword path assignment and search | Fully implemented and tested | Exact and whole-branch rules are available in Advanced Search and Smart Albums. Vocabulary entries can start a search directly. Existing Keyword rules find flat tags and vocabulary term names. |
| Advanced keyword controls | Partially implemented | Remaining work includes keyboard cycling between preset groups. |
| XMP keyword hierarchy exchange | Fully implemented and tested | Import reads Lightroom-style paths from embedded XMP or matching sidecars. File → Import XML / XMP Metadata can apply a sidecar to an existing photo. Export can write matching XMP sidecars for adjusted or original files. Flat IPTC keywords remain available for applications that use them. |
| IPTC title, creator, copyright and credit | Fully implemented and tested | Edit individual photos in Info → IPTC Metadata or preview replacements and clears in Batch Change. Creator order is preserved. Edits support Undo/Redo and exchange through embedded IPTC and XMP sidecars. |
| Search by IPTC title, creator, copyright and credit | Fully implemented and tested | Quick Search reads saved fields. Advanced Search and Smart Albums offer a rule for each field, and each creator can match separately. Search uses catalogue data and works with offline originals. [Aperture 3.5 Help](https://aperture.skydocu.com/en/organize-and-sort-photos/search-for-photos/search-using-a-combination-of-criteria/) |
| Catalogue-backed EXIF search | Fully implemented and tested | Advanced Search and Smart Albums support shutter speed, aperture, ISO, focal length and lens. Numeric and lens comparisons use saved capture values. Imports index EXIF automatically, and the Metadata menu indexes selected originals in older catalogues. Saved values work offline. [Aperture 3.5 Help](https://aperture.skydocu.com/en/organize-and-sort-photos/search-for-photos/search-using-a-combination-of-criteria/) |
| EXIF capture settings in Info | Fully implemented and tested | Info → EXIF reads the selected original in the background and shows shutter speed, aperture, ISO, focal length and lens. Missing values, offline originals and unreadable files have separate states. [Aperture 3.5 Help](https://aperture.skydocu.com/en/work-with-metadata/work-with-metadata-views/overview/) |
| Configurable metadata views in Info | Fully implemented and tested | General, EXIF Info, GPS, IPTC Core and Caption & Keywords are built in. Manage Metadata Views adds, duplicates, edits and deletes custom views. Custom field order and the active view are saved across libraries and launches. [Aperture 3.5 Help](https://aperture.skydocu.com/en/work-with-metadata/work-with-metadata-views/create-modify-and-manage-metadata-views/) |
| IPTC/EXIF/XMP, metadata views, custom fields and autofill | Partially implemented | Import reads selected embedded fields. Info edits captions, keywords and core IPTC fields. Export offers EXIF/IPTC/GPS and XMP sidecars. A full field editor, autofill and user-defined metadata fields remain open. |
| Batch captions and keywords | Fully implemented and tested | Metadata → Batch Change (⇧⌘B) and the selection bar preview the current and resulting values for the visible selection. The caption can be replaced or cleared independently. Keywords can be appended, replaced or cleared. Append keeps existing keyword order and skips case-insensitive duplicates. The batch saves as one Undo step. [Aperture 3.5 Help](https://aperture.skydocu.com/en/work-with-metadata/batch-change-metadata/) |
| Reusable metadata presets | Fully implemented and tested | Save a named preset from the checked fields in Batch Change. Load it for a reviewed edit or select it during import. Presets cover captions, flat keywords and the four editable IPTC fields. [Aperture 3.5 Help](https://aperture.skydocu.com/en/work-with-metadata/work-with-metadata-presets/create-metadata-presets/) |
| Selective Lift and Stamp | Fully implemented and tested | Lift copies adjustments, caption, keywords, rating and four IPTC fields. Stamp applies checked values to one photo or the visible batch selection. A mixed stamp is one Undo step. Explicit IPTC clears are supported, and missing lifted values are skipped. [Aperture 3.5 Help](https://aperture.skydocu.com/en/make-image-adjustments/ways-to-perform-adjustments/apply-standard-adjustments/) |
| Catalogue inherited IPTC from originals | Fully implemented and tested | Metadata → Catalogue IPTC from Originals verifies original fingerprints, previews additions and retains stored values and clears. Added fields are searchable and can be undone together. |
| Broader batch metadata and preset management | Partially implemented | Batch Change covers captions, keywords and four IPTC fields. Creating a preset from a version, in-place preset editing, direct application from Info and editing the remaining IPTC fields are open. |
| Adjust Date and Time for photo versions | Fully implemented and tested | Metadata and Info open a capture-time preview. A batch can preserve intervals relative to a dated selection or assign the same time to all selected versions, including undated photos. Each operation uses one Undo step and updates date-based browsing and Smart Albums. Adjusted exports can include the corrected EXIF capture time. Isonique preserves the original files. Aperture also offered an option to change the originals. [Aperture 3.5 Help](https://aperture.skydocu.com/en/work-with-metadata/adjust-the-photo-date-and-time/) |
| Duplicate detection | Implemented but needs improvement | Exact SHA-256 on import. No library-wide visual similarity review or comparison tools. |
| Photo Trash and Put Back | Fully implemented and tested | Sidebar, photo context menu, File command (⌘Delete), batch actions and edit history. Restores project, albums, stack, edits and original identity. Tested with restart, backup, and native controls. |
| Empty Library Trash and Finder Trash handoff | Fully implemented and tested | File and the Trash browser review records and managed candidates before removal. Originals used by active versions and referenced originals stay in place. Unavailable or changed managed originals keep their records in Library Trash. Pending Finder moves can be retried after reopening. |
| Container Trash | Missing | Library Trash supports photo and version records. |
| Export a project as an independent library | Fully implemented and tested | File and the project context menu export active project photos with their edits, versions and relevant albums and stacks. Both managed and referenced originals are copied and verified. Aperture also exported folders and albums and offered preview inclusion. [Aperture Help](https://aperture.skydocu.com/en/work-with-projects-and-the-library/work-with-library-files/merge-libraries/) |
| Import an exported project as a separate project | Fully implemented and tested | File → Import Project Library verifies and copies a self-contained project export. It remaps colliding IDs and preserves edits, versions, albums, stacks and surviving pairs. The import publishes one catalogue update and cleans up its copies on cancellation or failure. |
| Merge libraries | Partially implemented | File → Merge Project Library reconciles a self-contained export with its matching project by stable IDs and previews three-way changes and optional Trash moves. File → Merge Libraries reviews additions and identity conflicts across a whole Isonique catalogue, adds compatible records in one transaction, and reuses matching originals. Optional two-way review can apply imported edits and metadata. A separate opt-in previews explicit source Trash for matching photos and moves them to Library Trash. Inferring whole-library deletions from missing records remains outside the merge policy. [Apple Aperture 3 User Manual](https://www.manualshelf.com/manual/apple/aperture-3-upgrade/operation-manual-english/page-135.html) |
| Vaults, backup, verification and restoration | Implemented but needs improvement | Independent verified snapshots and restore to a new folder. Copies managed originals and preserves external paths without copying their files, as with historical Aperture vaults. No incremental vault updates or scheduling. |
| Library First Aid, permissions and catalogue repair | Partially implemented | File → Library First Aid reports missing managed originals, offline references, untracked managed files and paths that require inspection. Recovery and reconnect actions use verified matches. Untracked file inspection compares fingerprints with catalogue records and selected backups, then offers reviewed quarantine and restore actions. A live catalogue check protects claimed paths. Check Library Integrity verifies original hashes. Permissions repair and catalogue rebuild remain open. |
| Aperture/iPhoto interchange | Partially implemented | Read-only staged extraction of embedded originals plus some embedded metadata. No import of proprietary database relationships, referenced originals, historical adjustment recipes or vault format. |

## Image adjustment controls

| Workflow | Status | Isonique implementation |
| --- | --- | --- |
| Exposure, contrast, saturation, preset monochrome | Implemented but needs improvement | Shared renderer, numeric fields, resets and tested pixel results. 8-bit sRGB intermediate and adjustment clipping limit grading latitude. |
| Exposure brightness, recovery, black point and highlight/shadow detail | Partially implemented | Shadows, highlights and a Levels black point are real. Midtone-weighted brightness is available. Highlight recovery and extended-range RAW treatment remain absent. |
| White balance and tint | Implemented but needs improvement | Temperature is stored from 2000 K to 12000 K with a separate green/magenta Tint control. Sample Neutral uses the full-resolution Viewer Loupe to derive both values from an opaque, unclipped grey or white pixel before white-balance processing. The recipe, Viewer and export share one renderer; older Warmth recipes retain their prior appearance. RAW camera-neutral metadata, adjustable sample areas, automatic skin-tone or natural-grey modes and extended-range processing remain unavailable. |
| Enhance, vibrancy, definition, color correction and targeted color | Implemented but needs improvement | Vibrancy scales saturation by relative chroma. Definition provides bounded luminance local contrast with strength and a resolution-independent radius from 0.25% to 8% of the shorter image side; flat fields and colour differences are preserved. Targeted Color supports multiple reusable or duplicated ranges with circular hue matching, a fully affected core, smooth falloff and independent Hue, Saturation and Luminance. Built-in red/orange/yellow/green/cyan/blue/magenta ranges and full-resolution Viewer Loupe sampling are available. These use the shared Viewer/export renderer. Skin-tone protection, auto enhance and tint wheels remain open. |
| Curves and Levels | Partially implemented | Master and editable red/green/blue/luminance curves, stage-specific histograms, combined and individual RGB Levels with quarter-tones, and percentile-based Auto Levels with persisted clipping settings. Combined luminance and Separate RGB Auto Curves use input-histogram percentiles, and the Viewer Loupe can insert or select a curve point at the sampled input. Dedicated black, gray and white target eyedroppers, adjustable sample size, a working-space mode switch and extended-range processing remain open. [Aperture Curves](https://aperture.skydocu.com/en/make-image-adjustments/apply-specific-standard-adjustments/curves/), [Aperture Levels](https://aperture.skydocu.com/en/make-image-adjustments/apply-specific-standard-adjustments/levels/) |
| Global sharpening, edge sharpening and luminance noise reduction | Implemented but needs improvement | Detail recipes provide independent global and edge-masked luminance sharpening plus edge-preserving luminance noise reduction. Flat fields remain neutral, high-contrast boundaries are protected during reduction, and colour differences are preserved. The shared full-resolution Viewer/export renderer applies reduction before retouching and sharpening afterward. Radius, edge threshold, falloff, halo suppression and colour-noise controls remain fixed or unavailable. |
| Chromatic aberration, vignette and devignette | Implemented but needs improvement | Independent Red/Cyan and Blue/Yellow sliders resample those channels radially with clamped source edges. Devignette brightens source-frame falloff before retouching and geometry; Vignette darkens the final cropped and rotated frame. All four values use the shared full-resolution Viewer/export renderer and separate Lift/Stamp group. Automatic lens profiles, aberration detection, per-channel scale limits and adjustable vignette radius or softness remain unavailable. |
| Rotate and straighten | Implemented but needs improvement | Pixel geometry tested, including blank-corner trimming. Rotation/angle clears an existing crop. |
| Crop, presets, custom ratio and guides | Implemented but needs improvement | Draw/move/resize, aspect lock, orientation presets and pixel dimensions. Crop edges round to available pixels at render resolution. |
| Flip and orientation | Implemented but needs improvement | EXIF normalization, quarter turns and horizontal/vertical flips are in the renderer. Flip preserves the crop subject and is available in the Photos menu, edit strip and Inspector. Pixel and export tests cover orientation. The native Photos menu flip and Undo were exercised. |
| Spot removal, repair, clone and patch | Fully implemented and tested | The Viewer supports multiple ordered, editable spots with separate source and destination points, size and Repair or Clone mode. Repair transfers texture while adapting it to the destination colour; Clone copies source pixels directly. Recipes use source coordinates, clip safely at image edges, survive crop/rotation/flip/straighten/lens geometry and render through the same full-resolution preview/export path. Each creation, point move, mode, size, deletion and reset is non-destructive and undoable. |
| Red-eye correction | Implemented but needs improvement | Manual Red-Eye in Photos, the Viewer Retouch menu and Adjustments supports multiple independently editable pupil regions with source-space position, pupil size and darkness. The renderer changes only red-dominant pixels inside a feathered circular region, clips safely at image edges and preserves neutral or non-red pixels. Creation, movement, size, darkness, deletion and reset are undoable; recipes persist in their own Lift and Stamp group and use the shared full-resolution Viewer/export renderer. Automatic eye detection remains unavailable. |
| Black-and-white channel mix, monochrome tint and sepia | Fully implemented and tested | Black & White mixes bounded red, green and blue contributions with Rec. 709 neutral defaults. Zero-to-double channel controls support independent colour isolation and clipping-safe output. An optional tint provides hue and strength controls while preserving HSL lightness. The monochrome preset now uses the mixer; older saturation-zero recipes remain unchanged. Black & White is a separate Lift and Stamp group and uses the shared full-resolution Viewer/export renderer before Levels and Curves. Adjustable Sepia and its preset remain available independently. |
| RAW fine-tuning and decoder reprocess | Missing | ImageIO decoding depends on the host. Four real ARW, CR3, NEF and DNG files passed import and tonal editing on the tested Mac. RAW-specific controls and decoder reprocessing remain open. |
| Local Dodge, Burn, Saturation, Definition, Sharpening, Luminance Noise Reduction, Contrast, Blur, Tint, Skin Smoothing, Polarize and Halo Reduction; size, softness, strength, edge detection, erase, overlay, inversion, opacity and multiple instances | Fully implemented and tested | Each of the twelve non-destructive local effects supports multiple independently named instances from Photos, the editing strip and the Inspector. Instances own their strokes, mask opacity, inversion, enabled state and type-specific parameters and can be created, renamed, reordered, duplicated or deleted with Undo/Redo. Polarize darkens and increases saturation in cool chromatic sky-like pixels through a bounded intensity control. Halo Reduction suppresses local luminance overshoot using bounded amount and radius controls after sharpening. Same-type instances composite in their displayed order while the renderer retains established processing stages between effect types. Strokes use source coordinates, optionally protect luminance boundaries and work in Fit or pixel-zoom view. Coloured overlays follow geometry in the Viewer but never enter export. Format-31 single masks migrate without pixel changes; format 33 stores the two newest identifiers and parameters; format 34 adds optional pressure samples without changing fixed recipes. Recipes, Lift/Stamp and explicitly spatial custom presets preserve the instance list. The shared full-resolution preview/export path preserves original bytes. [Aperture Dodge](https://aperture.skydocu.com/en/make-image-adjustments/apply-specific-quick-brush-adjustments/dodge-lighten/), [Aperture Burn](https://aperture.skydocu.com/en/make-image-adjustments/apply-specific-quick-brush-adjustments/burn-darken/) |
| Pen pressure for local brushes | Implemented but needs improvement | Native AppKit input recognises pen and eraser tablet events and captures bounded pressure at each source-coordinate point. Size and strength independently select Off, Soft, Linear or Firm response curves and saved minimum values. The resulting per-point scales are part of the non-destructive format-34 recipe, so Viewer and export rendering remain deterministic. Mouse, trackpad and format-33 fixed strokes keep radius and strength at their configured values. Automated tests cover simulated tablet samples; physical-tablet interaction remains a hardware QA check. [Aperture Quick Brushes](https://aperture.skydocu.com/en/make-image-adjustments/ways-to-perform-adjustments/apply-quick-brush-adjustments/), [Aperture brush controls](https://aperture.skydocu.com/en/make-image-adjustments/ways-to-perform-adjustments/work-with-brush-strokes/) |
| Local brush rendering performance | Fully implemented and tested | Viewer, mask overlay and export share a 128 MiB, 12-entry source-space mask LRU. Exact recipes reuse their raster; an append-only painting session copies the longest valid prefix and rasterises only new strokes. Earlier-stroke edits, source dimensions and edge-aware pixel fingerprints invalidate reuse. Mask resolution remains bounded to 2048 pixels on the longest edge. Cancellation checks prevent cancelled work from being returned or cached. Automated budgets cover a 12,000 × 8,000 source and a 24-stroke session; broader real-world profiling with large RAW files remains desirable. |
| Adjustment presets, custom recipes, Lift/Stamp, reset and history | Implemented but needs improvement | Five built-in presets plus reusable custom presets saved across libraries. Custom presets capture selectable groups from the current photo and support create, update, rename and delete. A required review lists target versions and the groups that will change before single or batch application. Geometry, local brushes, Repair/Clone and red-eye are excluded by default and require explicit selection. Selective/batch Stamp, individual/reset-all and optional bounded persistent Undo/Redo are available. Batch preset Undo restores one changed photo at a time. A named global history browser and preset import/export remain unavailable, and a slider can save many intermediate events. |

## Proposed modern work

16-bit or float processing, wide-gamut/EDR previews and exports, measured CPU/GPU selection, cancellable render scheduling, bounded thumbnail caching, catalogue scaling, undo coalescing and recovery after interruption are modernization work. Vision face detection is a candidate for local processing. GPS browsing can use embedded coordinates with optional map tiles. Neither task requires an account for the local library. Proprietary Apple artwork, historical pixel formulas and direct legacy catalogue writes are outside this implementation.

Baseline persistence bugs fixed include partial import records and in-memory photo edits that survived a failed catalogue save. Remaining risks include overlapping preview renders during slider drags, repeated catalogue scans and sorting in view updates, and missing large-library and physical camera tests.
